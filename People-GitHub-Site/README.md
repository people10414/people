# People — Recordings / Studio

복고풍 헤더, 큰 사진 배너, 2열 음반 카탈로그와 문자 사진으로 구성한 정적 사이트입니다. 메인에서 KO / EN / JA와 다크 / 라이트를 전환할 수 있습니다. 선택한 언어와 모드는 방문자의 브라우저에 저장됩니다.

## 관리자에서 수정하기

배포 주소 뒤에 `/admin.html`을 붙이면 Studio가 열립니다.

1. 음반 제목·형식·발매일·커버·음원 링크와 순서를 수정합니다. 언어별 앨범명은 선택 사항이며, 비워 두면 원래 제목을 사용합니다.
2. 소개와 멤버 역할은 한국어·영어·일본어를 각각 작성합니다. 팀 이름, 로고, 연락처도 변경할 수 있습니다.
3. 화면 탭에서 첫 방문 언어·모드, 색상, 먼지 질감, 채도, 커서, LP 호버 움직임을 조절합니다.
4. 옆의 미리보기 또는 `전체 미리보기`로 확인합니다. 편집 미리보기는 선택한 기본 언어·모드를 따릅니다.
5. `배포 ZIP 내보내기`를 누르면 현재 내용과 사이트 파일 전체가 내려받아집니다.

편집 내용은 현재 브라우저의 IndexedDB에 임시 저장됩니다. 저장 공간이 지원되지 않으면 localStorage를 사용합니다. 기기·브라우저 변경 또는 브라우저 데이터 삭제 전에 JSON 또는 ZIP을 저장하세요. `현재 배포 내용 불러오기`는 브라우저의 초안을 배포된 내용으로 교체합니다.

이 관리자에는 서버 로그인이나 GitHub 쓰기 권한이 없습니다. 방문자가 자신의 브라우저에서 편집해도 공개 사이트는 바뀌지 않습니다. 공개 내용은 저장소 소유자가 파일을 올려 배포할 때만 바뀝니다. 비밀번호나 토큰을 사이트 파일에 넣지 마세요.

## GitHub Pages로 처음 배포하기

1. Studio에서 내보낸 `People-GitHub-Site.zip`을 압축 해제합니다.
2. GitHub에 저장소를 만들고 압축 안의 **내용물**을 저장소 최상위에 올립니다. 폴더 전체를 한 단계 안쪽에 넣지 않도록 `index.html` 위치를 확인합니다.
3. `Settings → Pages → Build and deployment`에서 `Deploy from a branch`를 선택합니다.
4. 브랜치는 `main`, 폴더는 `/(root)`로 지정하고 저장합니다. 저장소에서 Pages 사용을 지원해야 합니다.
5. GitHub가 표시하는 배포 주소를 엽니다. 프로젝트 주소가 `/저장소명/`으로 끝나도 상대 경로로 작동합니다.
6. 같은 주소의 `admin.html`에서 계속 편집할 수 있습니다.

Node, npm, 빌드 명령, ChatGPT API 키 없이 실행됩니다. 포함된 `.nojekyll`은 정적 파일을 그대로 배포하도록 합니다. 숨김 파일이 업로드 화면에서 보이지 않으면 Git으로 함께 올리거나 GitHub에서 `.nojekyll` 파일을 생성할 수 있습니다.

공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## 이후 수정 반영하기

- 간단한 콘텐츠·색상 변경: `data.json 다운로드` 후 저장소의 `data.json`을 교체하고 커밋합니다.
- 전체 백업 또는 다른 곳으로 이전: ZIP을 다시 내보내 저장소 파일을 교체합니다. ZIP은 현재 내용으로 HTML과 `content-defaults.js`도 갱신합니다.
- 새 이미지를 경로로 지정했다면 해당 파일도 `assets/`에 함께 올려야 합니다. 편집기의 `이미지 업로드`를 사용하면 이미지가 데이터에 포함되어 JSON만 교체해도 됩니다.
- 게시 전 미리보기에서 긴 제목, 여러 음반, 모바일 화면도 확인하세요. 정적 배포 완료까지 잠시 시간이 걸릴 수 있습니다.

`data.json`을 읽지 못할 때는 `content-defaults.js`의 이전 기본값을 사용합니다. 검색/공유 미리보기에는 HTML의 기본 정보가 쓰일 수 있으므로 제목·로고·소개를 크게 바꾸었다면 전체 ZIP으로 갱신하세요.

## 이미지

JPG·PNG·WebP를 업로드할 수 있으며 한 장당 최대 4MB입니다. 업로드 이미지는 base64로 JSON에 들어가므로 파일 크기가 증가합니다. 적절히 압축한 1000–1600px 이미지를 권장합니다. 직접 입력하는 로컬 경로는 `assets/cover.jpg`처럼 영문 파일명을 사용하세요.

외부 이미지에는 실제 이미지 파일 URL이 필요합니다. Instagram 게시물 주소는 이미지 주소가 아닙니다. 외부 이미지 서버의 정책에 따라 표시가 제한될 수 있으므로 직접 업로드 또는 로컬 파일 사용을 권장합니다.

## 구성

- `index.html`, `edition.css`, `site.js`: 공개 화면, 언어 전환, LP 인터랙션, 라이너 노트, Side B, Objects
- `admin.html`, `admin.css`, `admin.js`: 편집, 임시 저장, 미리보기
- `data.json`: 배포되는 콘텐츠
- `content-defaults.js`: 초기 화면 및 데이터 로딩 실패 시 기본값
- `content.js`: 데이터 검증·저장·다운로드
- `export-site.js`, `portable-files.json`: 의존성 없는 정적 사이트 ZIP 내보내기
- `assets/`: 음반·로고·질감·커서

글꼴은 Google Fonts의 Inter와 Noto Sans KR/JP를 사용하며, 연결되지 않으면 시스템 산세리프로 표시됩니다. 듣기 버튼은 등록한 음원 서비스로 이동합니다. 음악을 자동 재생하지 않습니다. 커서는 마우스가 있는 기기에 적용되고, 운영체제의 동작 줄이기 설정에서는 애니메이션을 줄입니다.

## 라이너 노트

음반 편집 항목의 `라이너 노트 · 음반 뒷면`에서 트랙리스트(한 줄에 한 곡), 크레딧, 언어별 짧은 메모를 입력합니다. 비운 항목은 숨겨집니다. 사이트의 음반 상세는 재킷 뒷면처럼 표시되며 `커버 보기`로 앞면과 번갈아 볼 수 있습니다. 제공되지 않은 트랙명과 크레딧은 기본 데이터에 넣지 않았습니다.

## Side B

녹음 제목과 파일 또는 실제 음원 URL을 등록하세요. MP3를 권장하며 업로드 한도는 한 파일 8MB입니다. MP3·M4A·WAV·OGG·WebM을 지원하며 실제 재생 가능 코덱은 방문자의 브라우저에 따라 다릅니다. 짧은 데모, 합주, 기타 루프를 직접 준비해 올리는 기능으로, 기본 배포에는 임의의 음악을 넣지 않았습니다.

음원은 자동 재생되지 않으며, 재생 시 LP가 회전합니다. 창을 닫거나 다른 녹음을 선택하면 멈춥니다. 재생 위치를 조절할 수 있습니다. 녹음이 없으면 빈 상태를 표시하며 관리자에서 Side B를 숨길 수도 있습니다.

업로드 음원은 JSON에 포함됩니다. 여러 음원으로 JSON이 커지면 `assets/demo.mp3` 같은 로컬 경로 또는 외부 음원 URL을 이용하세요. 로컬 경로를 지정하면 파일도 저장소에 올려야 합니다. ZIP에는 서버에서 불러올 수 있는 로컬 미디어가 포함됩니다. JSON 가져오기는 최대 64MB입니다.

## Objects — 전시에서 판매로

- `전시만`: 사진, 이름, 설명과 원본 게시물만 표시하며 가격·구매 버튼은 숨깁니다.
- `판매`: 가격과 외부 구매 링크를 모두 입력하면 구매 버튼이 표시됩니다.
- `품절`: 품절 문구를 표시하고 구매 버튼을 숨깁니다.
- `숨김`: 해당 오브젝트를 공개 화면에서 제외합니다.

아이템마다 사진 3장, 언어별 이름·설명, 순서를 관리할 수 있습니다. 현재 핀버튼은 전달받은 Instagram 게시물에 연결되어 있습니다. 대표 사진이 없을 때 해당 게시물을 삽입하며, 플랫폼의 로그인·삽입 정책 또는 접속 상태로 표시되지 않을 수 있어 원본 링크도 항상 제공합니다. 핀버튼 사진을 직접 업로드하면 삽입 게시물 대신 사이트 색감에 맞춘 사진 갤러리로 표시됩니다.

판매는 외부 스토어의 상품 또는 결제 페이지로 연결하는 구조입니다. 이 정적 사이트에 장바구니, 결제 처리, 주문 데이터베이스, 실시간 재고 기능은 포함되지 않습니다. 판매 시작 시 주문·결제·배송·재고는 연결한 스토어에서 관리하세요.

## 통화별 가격과 상단 메뉴

관리자 → Objects · 굿즈 → 판매 연결 설정에서 KRW(원화), JPY(엔화), USD(미국 달러) 금액을 각각 입력합니다. 원화·엔화는 정수, 달러는 소수 둘째 자리까지 입력할 수 있습니다. 통화 기호나 쉼표 없이 숫자만 입력하세요. 자동 환율 변환은 하지 않습니다.

한국어 화면은 KRW, 일본어는 JPY, 영어는 USD 금액을 표시합니다. 해당 금액이 비어 있으면 선택한 기본 통화, 그다음 입력된 다른 통화 순서로 표시합니다. 이전 버전의 단일 가격도 새 통화별 가격이 없을 때 유지됩니다. 전시 상태에서는 가격이 표시되지 않습니다. 실제 결제는 외부 구매 링크에서 진행되므로 해당 스토어의 금액과 지원 통화도 별도로 맞춰 주세요.

Side B와 Objects는 메인 상단의 소개 옆에 배치했습니다. 모바일에서는 콘텐츠 메뉴를 별도 줄로 표시합니다. People 워드마크와 영문 제목은 Shrikhand, 영문 본문은 Space Mono를 사용합니다. 폰트 파일과 OFL 라이선스가 assets/fonts/에 포함됩니다. 한국어·일본어는 Noto Sans와 시스템 글꼴로 표시됩니다.

## 레퍼런스 기반 레이아웃

홈은 사진 배너와 2열 음반 카탈로그입니다. 음반을 누르면 기존 LP 감상실이 열리고, 라이너 노트와 커버 전환, 외부 듣기, 이전·다음 음반 이동을 이용할 수 있습니다. 헤더의 ▶도 감상실을 엽니다. Side B, Objects, 언어·모드 전환, 커서는 유지됩니다.

관리자 → 배너·사진에서 메인 사진, 사진의 세로 위치, 선택적인 언어별 배너 문구와 소개 사진 두 장을 수정할 수 있습니다. 소개 사진은 브라우저에서 문자 그림으로 처리되며 사이트 글씨 색을 따릅니다. 외부 이미지가 CORS 처리를 허용하지 않으면 실제 사진으로 표시됩니다. 직접 업로드 또는 assets/의 로컬 이미지를 권장합니다. 문자 이미지 설정을 끄면 흑백 사진으로 표시됩니다.

West Mineral의 제공된 캡처를 참고해 People의 실제 자료로 재구성했습니다. 원본 사이트에 직접 연결하지 못해 원본 폰트·홈 배너를 동일하게 복제한 결과는 아닙니다. 사진과 로고는 기존 People 자료이며, 새 제목/본문 폰트는 자유롭게 사용할 수 있는 Shrikhand와 Space Mono입니다.


## 메인 로고와 언어
메인에는 공식 피플 로고를 표시합니다. 관리자 → 로고·사진에서 교체할 수 있습니다. 한국어 모드의 메뉴와 일반 콘텐츠는 English 값을, 주요 소개는 한국어 값을 사용합니다. 일본어 모드는 日本語 값을 사용합니다.

## 재배포
관리자에서 편집한 후 GitHub 배포 ZIP을 내려받아 압축을 풀고 저장소의 기존 파일을 교체한 뒤 커밋합니다. ZIP 파일 자체를 올리는 것이 아닙니다. 관리자 변경은 브라우저 임시 저장이며 GitHub에 자동 전송되지 않습니다.
